Per-agent starting points. Verified 2026-09-17 against the `agents` image;
treat as a hint, not gospel - check `--help` first, versions move. All four do
support the ChatGPT Plus/Pro subscription, each under its own name for it.

codex (0.154.0)
  bypass:  codex --dangerously-bypass-approvals-and-sandbox
  auth:    codex login --device-auth       -> prints URL + one-time code
  model:   /model in the TUI. Slugs have no provider prefix here, e.g.
           gpt-5.6-luna. Persists to ~/.codex/config.toml as `model` and
           `model_reasoning_effort`.
  effort:  the top-level list stops at "Extra high"; max is one level deeper,
           under "More reasoning...". Config value is "max". /status should
           read "gpt-5.6-luna (reasoning max, ...)".
  resume:  codex resume <session-id> -C <dir>
           ids in ~/.codex/sessions/ and ~/.codex/session_index.jsonl

pi (0.85.1)
  bypass:  nothing found to bypass - `pi --help` lists no approval or sandbox
           flags. -a/--approve only trusts project-local files (AGENTS.md and
           friends). Confirm it really does not prompt before relying on this.
  auth:    /login inside the TUI, pick "ChatGPT Plus/Pro (Codex)". Tokens land
           in ~/.pi/agent/auth.json and auto-refresh. `pi auth check
           --provider <p>` verifies. Note the default provider is google, so
           the model must be selected explicitly after login.
  model:   --provider <p> --model <pattern|provider/id>; `pi --list-models
           [search]` shows real slugs (empty until you are logged in).
  effort:  --thinking max        (the ladder is off|minimal|low|medium|high|
                                  xhigh|max - max is the top)
  resume:  pi -r (picker), pi -c (continue last), pi --session <path|id>

opencode (1.18.30)
  bypass:  opencode --auto        (auto-approve all not-explicitly-denied)
  auth:    opencode providers login -> search "openai" -> OpenAI -> pick
           "ChatGPT Pro/Plus (headless)", NOT the browser option and not the
           API key one. Creds land in ~/.local/share/opencode/auth.json;
           `opencode providers list` shows what is stored.
  model:   -m openai/<model>; `opencode models openai` lists them.
  effort:  no CLI flag, and it is not in the model picker either. It is a model
           *variant*: press ctrl+t in the TUI ("Variant cycle") to walk
           none->low->medium->high->xhigh->max. The status bar then reads
           "... GPT-5.6 Luna OpenAI - max". It defaults to *none*, so an
           untouched run does no reasoning at all. Two routes silently do
           nothing and must not be trusted: `reasoningEffort` under
           provider.models.<id>.options in opencode.json (`opencode debug
           config` echoes it back as if applied), and a "#max" suffix on the
           model string. Verify with `opencode export <sessionID>` - assistant
           messages carry a `variant` field; "max" is proof, null means it fell
           back to none. Don't judge it by reasoning-token counts, they are
           small per turn even at max. The variant does persist across resume.
  resume:  opencode -s <sessionID>, or -c for the last;
           `opencode session list` to find the id

hermes (0.21.2)
  bypass:  hermes --yolo
  auth:    hermes auth add --type oauth openai-codex --no-browser
           (`hermes login` is deprecated). `hermes auth list` and
           `hermes auth status` show what is stored; `hermes model` picks
           provider + model, `hermes status` shows the active config.
  model:   -m <provider/model> --provider <p>
  effort:  --reasoning max       (the ladder is none|minimal|low|medium|high|
                                  xhigh|max|ultra - stop at max, ultra is
                                  above it and I do not want it)
  resume:  hermes -r <id|title|latest>, hermes -c [name], `hermes sessions`
           to list
